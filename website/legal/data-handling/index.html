Draft notice

Data Handling

A plain-language description of how Mellorca intends to handle operational enquiry data. This must be reconciled with the production stack and legal requirements before launch.

Collect only useful context

The initial contact form is intentionally limited. It asks for enough information to understand the enquiry without turning first contact into a procurement questionnaire.

Do not request secrets in the enquiry form

Visitors should not submit passwords, API keys, financial credentials, private keys or other system secrets through the public contact form.

Access should follow project need

If a project proceeds, system access should be requested deliberately, limited to the work being performed and removed when no longer required.

Document operational ownership

Where Mellorca builds integrations, workflows or automation, ownership and support expectations should be documented rather than left implicit.

Production dependency

The current Pages Function forwards valid enquiries to a deployment-configured webhook. The final notice must reflect the real webhook/CRM provider, retention practices, access controls and any analytics tooling actually enabled.
